# ANALYSIS_QUALITY_RULES — 分析出力の品質規約(正本・v1)

クラウド裁定者が維持する「**自分を騙さないための規律**」。ISSUE_MAP(何を問うか)の対に位置し、
**答える時に踏んではいけない飛躍**を定める。value-audit・日次分析・レーン投稿・教材の全出力に適用。
出典=Codex実行役の分析品質監査(2026-07-10・実際の分析出力の7指摘+2追加)。全採用。

## R1. 指数間の非比較性
- 算出方法・水準の異なる指数の**ポイント差・幅を直接比較しない**(日経平均の円 vs JPX日経400のpt等)。
- 市場の広がり(breadth)は**専用データで**判定: TOPIX騰落率 / 騰落銘柄数 / 等加重リターン / 寄与度。
  これらが無ければ「広がりは不明(UNKNOWN)」と書く。「◯日ぶり反発」から値がさ株主導は導けない。

## R2. 時刻の分離(再現性)
- 分析出力に以下を必須で分離記録: `analysis_generated_at` / 各ソースの `*_observed_at`(nikkei/
  newspicks等)/ `market_session_date` / `comparison_snapshot_id`。
- 観測時刻より後の情報を使った箇所は明示(先読みでなくとも再現時の混乱を防ぐ)。
- ※ analysis_readiness_manifest(Phase 2c-2)と連動。

## R3. 反証表現の厳密化
- 1セッション/短期の価格方向で中期の因果経路を「反証した」と書かない。
  正: 「短期的に確認されなかった。遅行的影響までは反証していない」。
- 「明確な上昇トレンド」等の測定不能語を禁止。トレンド主張は**指標・期間・閾値・判定期限**を定義して
  初めて書ける(定義できないならUNKNOWN)。

## R4. 指数テーマ→個別銘柄の読み替え禁止
- SOX上昇→NVDA強気、主力ハイテク安→TSLA弱含み のような**指数から個別ティッカーの当日方向**への
  読み替えをしない(指数テーマと個別の当日方向は一致しない)。
- 正: 「半導体エクスポージャーに相対的に強い観測。ただし個別への方向読み替えは
  ティッカー別価格・材料未確認のためUNKNOWN」。
- 「ポジティブ材料が優勢」等、件数・重要度評価の無い総括は書かない。

## R5. 投資主体フローの期間整合
- 比較する需給フローの**集計期間を必ず確認**(海外投資家=通常週次 vs 個人=当日解説等)。
  期間が違うフローを「主体が分かれた」と並べない。期間不一致ならその旨を明記。

## R6. 報道の主張と、確認された因果の分離
- 記事・動画の「犯人は◯◯」等の主張は**報道の主張(INFERENCE/引用)**として書き、
  取得データで確認した因果と混ぜない。因果主張には裏付けデータを要求
  (例: レバETFなら売買代金・資金流入・対象株への寄与)。翌日の値動き継続は因果検証にならない。

## R7. レーン用語とSOURCE_CONTRACTの整合
- M0等の計器名は**採用済みSOURCE_CONTRACTと一致**させる。契約外の系列(例: 原油がM0-lite外)を
  「M0未実装」と書かない。別レーンのUNKNOWNとして分離する。

## R8. 見出し件数の三段表示(過大評価の防止)
- ニュース見出しは **raw件数 / URL重複除外後 / 同一クラスタ統合後** の3段を表示。
  複数セクションに同一記事が出るとテーマの強さを過大評価するため(nikkei dedup修正の一般化)。

## R9. 答え合わせは文章でなく機械可読の列で
- 予測・仮説の答え合わせは列で管理:
  `hypothesis_id / metric / source / threshold / deadline / current_status / falsified_at`。
  market_view_log・judgment_lane・codex_analysis_log を本スキーマに揃える(自動判定可能に)。

## 運用
- value-audit / 日次分析は出力前に本規約で自己点検。飛躍箇所はUNKNOWNへ戻す。
- 第2監査役・検証役は本規約を監査チェックリストに使う。
- 「分析結果より先に進んだ節(過剰主張)はUNKNOWNへ戻す」が既定の是正。
- 本規約の改版は裁定のみ。ISSUE_MAPと対で参照する。
