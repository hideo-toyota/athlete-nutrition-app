## DT-1a. 決算発表予定(将来分)

### 取得と保存
- 平日夕方に1回、決算発表予定を取得(LaunchAgent。ログはリポ外・既存レーンの流儀)。
- raw: `data/raw/jquants/announcement/<fetch_date>.json` + provenance
  (fetched_at / endpoint / params / plan / tos_personal_use_confirmed)。
- derived: `jquants_earnings_calendar_v1`(schema例: code / announcement_date /
  fiscal_period / source / first_seen_date / as_of)。
- **PIT原則(最重要)**: カレンダーは**追記型の履歴**として持つ。「fetch日Xの時点で
  発表予定日Yが既知だったか」を後から再構成できること(将来のバックテストで
  「決算を跨がない」ルールを検証する時、当時知り得た情報だけを使うため)。
  上書き更新(最新スナップショットのみ保持)は禁止。変更(日程変更・延期)も追記で記録。

### W2 の M 実数化(daily-update)
- M = ユニバース銘柄のうち announcement_date が**次の5営業日**に入る件数。
- 営業日判定は trading calendar を使う(D0で確認)。取得不能なら平日近似+
  「営業日判定は近似」と正直に注記。
- **鮮度ゲート**: カレンダーの最終取得成功が3営業日より古い場合、M を実数で出さず
  「UNKNOWN(calendar stale: last_fetch=YYYY-MM-DD)」に戻す(古いデータで安心させない)。

### 決算接近フラグ(investor-brief)
- overheat_flag と同型で `earnings_proximity_flag` を追加:
  該当窓 = **発表3営業日前〜発表翌1営業日**(BT-1事前登録の定義を維持。変更禁止)。
- 固定文言: 「⚠️ 決算接近: 発表予定 YYYY-MM-DD。BT-1検証によりこの窓の新規エントリーは
  行わない(防御ルール③)。保有分の売り指示ではない」
- 除外しない・売り指示にしない・閾値/窓のハードコード禁止(config `bt1_defensive.earnings_window`)。

### テスト(合成データ)
- 5営業日窓の境界(6営業日先は数えない/休日を挟む場合)
- 鮮度ゲート(4営業日前の取得→UNKNOWN表示)
- PIT再構成(fetch日X時点のカレンダーにYが含まれる/含まれない)
- 日程変更が追記され、最新日程がflagに反映される
- FORBIDDEN_OUTPUT_TOKENS 非抵触 / 既存341テスト非破壊

## DT-1b. 信用残(週次) / DT-1c. 空売り比率(DT-1a監査後に着手)
