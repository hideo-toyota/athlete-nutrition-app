## 1. 目的
新規の工程・新規の分析対象・新規レーンの**着手を月次の裁定ゲートに集約**し、「推測で前提を作らない／新規着手なし」の規律を**運用の速度に流されず**維持する。ゲートは容量（capacity）と DoD 衛生（hygiene）を守るためのブレーキであり、成果を増やすアクセルではない。

## 2. スコープ
- **ゲートを通す（要投入判定）**: 新工程の着手、新規銘柄ユニバースの拡張、新レーン新設、休眠レーンの起動。
- **ゲート不要（随時可）**: 継続観測、DoD クローズ、裁定済み SPEC の実装、障害の恒久修正、記録・報告の配送。

## 3. 月次サイクル（毎月 初週）
1. **棚卸し（intake review）**: ROADMAP の IN_SPEC / BLOCKED / DORMANT を一覧化。各項目の解除条件の充足状況を FACT で確認。
2. **容量判定（capacity）**: 単一書き手（ROLES §2.1）の制約下で、当月に**同時進行できる実装は原則1工程**。並行は継続観測・運用のみ。
3. **投入判定（admit / hold）**: 裁定者が当月の**投入1件**（＋継続観測）を選ぶ。残りは `hold` 理由付きで据置。
4. **発行（issue）**: 投入項目の SPEC を発行（`CLAUDE_HANDOFF_`）。書き手宣言→実装へ。
5. **記録**: 投入・据置の一覧を `radar-ops/reports/` に月次 `CONFIRM_intake_<YYYYMM>` で記録（判断記録レーンの月次ロールアップと相互参照）。

## 4. 投入基準（admit ゲートの必要条件・全て満たすこと）
- (a) 前工程が **DoD クローズ**済み（未クローズ工程がある間は新規投入しない）。
- (b) SPEC 化可能（前提が FACT で埋まっている。UNKNOWN が着手前提に残らない）。
- (c) 容量あり（同時実装1の枠が空いている）。
- (d) ANALYSIS_QUALITY_RULES に反しない（推奨化しない・PIT・秘密非扱い）。
- いずれか欠ける場合は **hold**（差し戻しではなく据置。理由を記録）。

## 5. 初回（2026-07 発効ラウンド）の適用
- 当月は**新規投入を1件に絞る**。候補と裁定:
  - **M0 v2 実装**: SOURCE_CONTRACT 確認（裁定 GO）＋FRED キーが埋まれば **admit 第一候補**。前提の一部（FRED/SOX/FX）が UNKNOWN のため、**契約確認後の限定実装**（NK225F・VIX・FRED着系列のみ）に絞って投入。
  - **Phase 2c-1 snapshot**: SPEC 発行で **admit 第二候補**（M0 と排他・容量1）。
  - **DT-1b 本実装**: G1 通過で解除済みだが、当月は **hold**（容量・順序）。
- 決定: 当月投入=**M0 v2 の限定実装**を第一に置き、SOURCE_CONTRACT GO とキー記入が揃い次第着手。揃わない場合は **2c-1 snapshot** に振替（どちらか1件）。DT-1b は 2026-08 ゲートへ hold。

## 6. 停止・逸脱
- ゲート外の新規着手要求は**停止**し、次回ゲートへ回す（緊急の障害修正は例外・記録する）。
- ゲート判定は裁定者が行う。オーナー直の投入指示はゲート記録に**逸脱として明示**したうえで実行してよい（ROLES §2.4 の形式逸脱記録に準じる）。
