# CLAUDE_HANDOFF — 週次判断記録レーン(judgment-log)仕様(ドラフト・発効はバッチ改版時)

クラウド側裁定者より。オーナー承認済み(所見6の採用+講義形式+新チャンネル)。
**実装着手はG1クローズ後**(本文書はバッチ改版で正式発効。それまで実装しない)。

## 0. 目的(この装置の北極星に直結)
decision_log が1件のままでは「裁量 vs DCA」の検証が空転する。オーナーの**見送り(pass)を含む
判断**を週次で記録し、P6較正チェックポイント(採用済み)で機械採点する閉ループを作る。
これは分析機能ではなく、**オーナー自身の判断力を計測する機能**である。

## 1. リズムと配信(自動)
- **毎週金曜 18:00 JST**、LaunchAgent `com.radar.judgment-log` が Discord 新チャンネル
  (オーナーが作成・webhook は `.discord_webhook_judgment`・education と同方式)へ投稿。
- 投稿の構成(毎週この型):
  1. **今週の判断機会**: 当週の Human Review List に登場した銘柄から、緊急度上位5件の要約
     (過熱/決算接近/急落など掲載理由つき。推奨ではないと明記)
  2. **今週の講義**(500字・判断基準カリキュラム): 見送り基準 / サイズ判断 / 反証設計 /
     「わからない」の技術 / アンカリング対策 / 機会費用 の6テーマをローテーション
  3. **記録の依頼**: 「今週、見た・見送った・検討した銘柄について2〜3件、
     下の型で返信してください」
     型: `銘柄 / 判断(見送り・監視継続・検証入り) / 理由1行 / 反証条件(あれば)`
- education レーンと同じ完全性ゲート(生成失敗時は正直な失敗通知・state無進行)。

## 2. 記録の取り込み(採点受信経路と共通化)
- オーナーの返信は education_grading_intake_fix.md で構築する受信経路(A/B いずれか)と
  **同じ配管**で回収し、decision_log.jsonl に append(scenario 事前宣言フィールド付き:
  継続/反落/見送り/決算待ち/過熱注意 のいずれかを記録時に確定。後から変更しない)。
- 各記録に P6 checkpoint を自動予約: **5営業日後・20営業日後・次決算後**。
  「見送り」の採点定義: 見送った銘柄のその後のリターンを記録するが、
  **見送り自体の正誤は単一銘柄では判定しない**(月次で「見送り群 vs 検証入り群」の
  分布比較のみ。1件の上昇で「見送りは失敗」と言わない — 後知恵バイアスの機械的排除)。
- 週の記録が0件なら翌週の投稿冒頭にリマインド1行(education と同思想: 責めない・事実だけ)。

## 3. 月次レビュー(裁定者の担当)
- 月末に decision_log + checkpoint 結果から「判断の型」レポートを裁定者が作成:
  見送り理由の分布 / 反証条件の質の変化 / scenario 宣言の的中傾向 / DCA対比の暫定値。
  education の弱点マップと同時に読む(判断と知識の両輪)。
- **採点は相対リターンで行う**(Codex提言 2026-07-08 採用): 各checkpointの評価は
  絶対リターンでなく「**同期間のTOPIX比**」と「**同期間の当該33業種指数比**」の2軸で記録
  (V2 indices/bars/daily を使用)。地合い・セクター追い風と判断の質を分離するため。
  絶対値も併記するが、判定には使わない。

## 4. 実装タスク分割(発効後・司令塔)
- J1: LaunchAgent+生成スクリプト(education の型を流用・完全性ゲート込み)
- J2: 返信取り込み→decision_log append(+scenario/checkpoint 予約)
- J3: テスト(型不正の返信→取り込まず確認を返す / 0件週→リマインド / FORBIDDEN 非抵触)
- DoD: 初回実配信+オーナーの実記録1件が decision_log に入り checkpoint が予約されること

## 5. 禁止
- 記録を促すために「候補銘柄」を提示しない(判断機会の要約は Human Review List の転記のみ)
- 見送り判断への評価的文言(「惜しかった」等)を出さない — 事実と分布だけ
- 週次投稿に売買推奨・ランキング・価格目標を含めない(FORBIDDEN ガード適用)

規律不変: push無し / append-only / PIT / 秘密非表示。
発効条件: バッチ改版時に INDEX へ登録・G1クローズ後に着手指示。
