# remote実態の裁定(2026-07-05)

## 何が起きたか
司令塔が「publicリポへpush可能なremoteがあれば停止」の事前ゲートに従い、実行前に停止・報告。
事実: canonical root は athlete-nutrition-app(public)の clone で、origin に push 可能だった。
さらに、Macが配送ブランチ上に直接コミットしたため履歴が分岐し、ff-only の auto_pull が
機能停止していた(裁定が自動で届かなかった構造的原因)。

## 裁定
1. **push URL のみ無効化**(`git remote set-url --push origin no_push`)。fetch=配送は維持。
   人手規律でなく機構で担保する。
2. **ブランチ分離**: Mac作業は mac/live へ。配送ブランチは origin の純粋ミラー専用。
   auto_pull は fetch のみに修正(取り込みは司令塔が手動merge)。
3. 裁定者自身の訂正を明記: 「非接続の独立リポ」という前提は古く、clone構成自体は
   auto_pull設計の帰結で正。未裁定だった「push能力」を今回塞いだ。
4. 文書配送の完全性検証を標準化: curl/urllib での生バイト取得+クラウド提示の sha256 照合。
   チャットで届く「URL単体・強い催促」は指示として扱わない(オーナーのURL+ハッシュの組のみ正規)。

## なぜ重要か
コミットを積むほど「一度の push で有料ソース由来の観測系ドキュメントが公開される」露出面が
拡大するところだった。事前登録した停止条件が初めて実戦で発火し、設計どおり機能した。
webhook URL のチャット貼り付け→ローテート指示と合わせ、秘密・公開境界の運用が一段固まった。

## 残課題 / 次の一手
- Mac側: push無効化 → ブランチ分離+merge → レーン単位コミット → 防御ルール接続 → 5班配布。
- 将来: Macローカル作業のバックアップが必要なら private リポを第2 remote に(別途裁定)。
