## 改善点(優先度順)

### 🔴 最優先(セキュリティ / 安全ゲート)

- [ ] **#1 REST clientがlive.pyを迂回し、トークンを非redactで例外送出**
  - `radar/sources/jquants_rest_client.py:14,30,43,49,50`(呼出 `features/jquants_rest.py:304-318`)
  - 独自に `urllib.request.urlopen` で `api.jquants.com/v1` へ接続(=2本目のネット出口)。`…/token/auth_refresh?refreshtoken=<秘密>` や mail/password を **try/except無し・redact無し**で送る。`HTTPError.url` にクエリ文字列(=トークン)が残り、例外伝播で露出。
  - `common._known_secrets()` は `JQUANTS_API_KEY`/`EDINETDB_API_KEY` のみ登録 → `JQUANTS_REFRESH_TOKEN`/`MAILADDRESS`/`PASSWORD`/idToken は redact 対象外。
  - 違反: 「ネット出口は live.py のみ」+「鍵は例外にも出さない」。
  - 修正案: REST取得を `live.UrllibClient`/`common.fetch` 経由に統一。全 urlopen を try/except で包み `_redact_with_key` で再送出。refresh-token/mail/password を秘密集合に登録。URLからクエリを除去してから例外へ。

- [ ] **#2 redact() のヘッダ穴(X-API-Key 素通り / Authorization が貪欲)**
  - `radar/sources/common.py:62-65`
  - dict-repr形式 `{'X-API-Key': 'SECRET'}` は既存ルールでマスクされない(検証済)。env外の注入鍵は値マスクも効かず漏れる。
  - `(?i)(authorization\s*:\s*)[^\n]+` は行末まで貪欲 → 同一行の別フィールドを巻き込む/順序次第で別の鍵が露出。
  - 修正案: ヘッダ規則を引用符・`[:=]` 許容に。値はトークン境界(`"` `'` `,` `}` 空白)で止める。可能なら headers を文字列化せず構造的に redact。

- [ ] **#3 禁止語ゲートが部分文字列一致のみで突破可能**
  - `radar/research/common.py:18-27,468-471`(`assert_no_forbidden_output`)
  - 完全一致の語(`buy_candidate`/`recommendation`/`期待リターン`/`ランキング` 等)だけ検出。`Buy`/`BUY`/`目標株価`/`target price`/`price target`/`rank`/`ranking`/`top pick`/`割安`/`強気`/`推奨`(おすすめ以外)は素通り。
  - これは買い候補・推奨漏れの**唯一の防壁**。
  - 修正案: 小文字化+空白正規化したテキストに対し、語境界の正規表現で照合。英語等価語(buy/sell/target price/rank/overweight 等)と和語(目標株価/割安/割高/強気/弱気/推奨)を追加。

- [ ] **#4 J-Quants raw取得・feature生成にコード上のToSゲートが無く無条件実行**
  - `radar/features/jquants_bulk.py` 全体 / `radar/sources/jquants_bulk.py`(raw gzip を `data/raw/jquants/bulk` へ保存) / `features/jquants_rest.py`
  - [[LICENSE_MATRIX]] では J2(raw保存)/J3(retention)/J5(第三者LLM入力)が今も**未確認(致命)**。橋渡しは 2026-06-20 の「本人判断 解除メモ」のみで、原本転記は未完。
  - コードには確認フラグ連動の guard が無く、解除前提が崩れても止まらない。
  - 修正案: `config` に `data_layer.providers.jquants.tos_personal_use_confirmed`(既定 false)を設け、全 J-Quants raw/feature 経路の入口で検査。false なら redact-safe な `SystemExit`。

### 🟠 高(正直さ / 再現性 / PIT)

- [ ] **#5 wall-clock混入で再現性が破れる(原則6「二度実行で同一」)**
  - `radar/report.py:167`(mirrorの鮮度行に `date.today()`)/ `journal.py:141,157`(ts・score既定asof)/ `value_store.py:264,286,324`(created_at)
  - `--asof` 省略時に今日日付を成果物へ埋め込み → 監査リプレイ不能。
  - 修正案: 永続成果物を書くコマンドは asof/now を明示注入。省略時のサイレント `today()` フォールバックをやめる(または使った asof を記録)。

- [ ] **#6 NaN/Inf を “確からしい数値” として出力(原則3違反)**
  - `radar/research/common.py:450-465`(`metric_value`)/ `investor_brief.py:45-75`(`_pct`/`_mult`/`_small_jpy`)/ `audit_report.py`(`_pct`/`_pt`)/ `evidence.py:127-130`/ `common.py:329-334`(`_calc_value`)
  - `nan%`・`inf JPY` が FACT/CALCULATION セルに出る。0除算等が UNKNOWN にならない。
  - 修正案: `math.isnan/isinf` を UNKNOWN 扱いに(整形ヘルパ全箇所)。

- [ ] **#7 index as_of が未来でも警告だけで未来weightを計算に使う(look-ahead)**
  - `radar/concentration.py:104-130`
  - journal は未来horizonをskipするのに、concentration は未来データを総計へ混入。不整合。
  - 修正案: 未来日付のindex寄与を総計から除外(UNKNOWN/その他扱い)、または asof違反を hard `SystemExit`。

- [ ] **#8 日次株価PIT(JST引け後に利用可)が未強制**
  - `radar/features/jquants_bulk.py:220,244` / `jquants_rest.py:62-63,83`
  - フィルタが `d > asof_date`(日付粒度のみ)。当日barを常に含む=intraday asofで look-ahead。summary `DiscDate`/dividend `PubDate` も日付のみ比較。
  - EDINET経路は `_asof_end_utc`(JST 23:59:59)で正しい。
  - 修正案: asof を tz-aware datetime で保持。株価は JST引け時刻の `available_at <= asof` を要求。開示は `DiscTime`/`PubTime` を見る。

- [ ] **#9 J-Quants derived に config_hash / code_commit が無く、raw purge後に再現不能**
  - `radar/features/jquants_bulk.py`(doc/manifest ~601-728)/ `jquants_rest.py`(~232-296)
  - EDINET側(`build.py:246-250`)は `config_hash`/`code_commit`/`normalization_version` を記録済。J-Quants側は未記録。RESTは入力payloadのhashも未記録。
  - 修正案: 両builderの doc+manifest に `config_hash`+`code_commit` を追加。RESTは取得payloadをhash化。

- [ ] **#10 composition_ref を無検証でパスとして開く(traversal)**
  - `radar/concentration.py:86` → `radar/data.py:27-33`
  - `portfolio.json` の `composition_ref` をそのまま `Path()` 化。`../../` 可。他箇所(`value_store.safe_output_path` 等)は base dir制限しているのに不整合。
  - 修正案: `indices/` 配下にホワイトリスト制限し、外を拒否。
