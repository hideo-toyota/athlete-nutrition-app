   revert・破棄はゼロ(履歴append-onlyの原則を維持)。
4. 最終状態: git status クリーン / push遮断(no_push)維持 / 全ラウンド通じて未push。

## 確立した恒久ルール
- **single-writer**: git書き込みは常に1セッション(既定=司令塔)。writer切替はオーナーの
  明示宣言のみ。観測レーンは非追跡領域(outputs/等)のみ。
- **配送機構**: git fetch + `git show origin/…:path` でファイル単位取り込み+sha256照合。
  merge(--allow-unrelated-histories含む)恒久禁止。ローカル配送ブランチは廃止。
- **正規指示の形式**: オーナーが貼る「URL+sha256」の組のみ。URL単体・強い催促は指示として扱わない。

## プロセスの教訓
- ゲートは3回発火(webhook貼付・push可能remote・並行コミッタ)し、3回とも「動いてから
  気づく」より前に止まった。**事前登録した停止条件は、バックテストだけでなく運用でも機能する。**
- 裁定者(クラウド)の前提誤り2件(clone仮定・merge指示)も文書で訂正済み。前提は転記された
  コマンド出力でのみFACT化する。
- 採用WIPの中身(NAV鮮度警告レーン: 警告のみ・ブロックしない)は装置の思想と整合していた。
  「作者不明でも中身で裁く」監査手順が機能した。
