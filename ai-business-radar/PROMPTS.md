# PROMPTS — Discord からの指示プロンプト集(① 1セッション + サブエージェント)

> Discord(または Claude Code)に貼って使う。`CLAUDE.md` が規律フローを強制するので短文でも動くが、
> 以下は「確実に規律を通す」版。**どの指示でも共通**: 買え/売れは断定しない・両論と不確実性を添える・
> 買い候補は discipline-auditor を通すまで出さない・最終判断は私(原則1)。

---

## A. 市況を知る(market-pulse)
```
今の市況を教えて。米国(S&P/Nasdaq・金利/10年債・主要マクロ)と日本(日経/TOPIX・USD/JPY)、
私の保有(NVDA/TSLA)に関わるニュースを、出典と取得時点つきで。
各保有について「この材料は“事業仮説”を壊すか?」だけ評価し、売買指示はしないで。
```
短縮: `今の市況は?` / `NVDAとTSLAに新しい材料ある?`

## B. 日本の新規候補を分析(equity-analysis / エッジ②)
```
日本株 <コード/社名> を規律あるワークフローで分析して。
① mirror で今の集中度 → ② market-pulse で最新 → ③ 財務分析(仮説 + 弱気シナリオを“対で”、
「この見方は既に株価に織り込まれてないか?」、見るべき決算KPI、反証可能な予測を1つ)→
④ devils-advocate で最強の反対論と“事業ベースの撤退条件” → ⑤ discipline-auditor で買い案を規律に通す。
両論 + 不確実性 + 規律判定を出して。買え/売れは言わない。決めるのは私。中小型・低カバレッジ優先。
```
注: 深い財務は web 取得 + 私が貼る決算短信で補う(J-Quants は未接続)。

## C. 保有を点検(NVDA / TSLA の仮説チェック)
```
保有の <NVDA / TSLA> を点検して。価格でなく「成長仮説(まだ成熟でなく成長余地/AI・EV優位)が無傷か」を、
最新の事実(決算・需要・競合・金利・織り込み)で評価して。
仮説が崩れる兆候(=撤退条件)が出ていないかだけ確認。基本は売らない前提。両論と不確実性を添え、断定しない。
```

## D. 売買案を規律ゲートに通す(check)
```
この売買案を規律ゲートに通して: <buy|add|trim|exit> <ticker> <金額> <セクター>
(過熱なら --overheated、ナンピンなら --thesis-intact --powder を付ける)
上限(2.5/5/10%)・過熱・ナンピン3条件・cost欠損を判定し、可否と理由だけ。買え/売れは言わない。
```
= `python3 -m radar check ...` を走らせる指示。

## E. 判断を記録(log)
```
今の判断を記録して。journal/decision_input.json を次で作って log して:
銘柄 / 口座 / アクション(buy_new等) / 理由 / 反証可能な予測(claim と horizon=YYYY-MM-DD) /
vs_discipline(規律を破るなら override + 理由) / size / ref_price / benchmark_ref。
予測が無い・override で理由が無いなら拒否でいい。
```

## F. 採点・較正(score / review)— 期日が来たら
```
期日が来た判断を採点して。journal/prices.json に horizon の終値(対象と BENCHMARK)を入れてから score、
その後 review。「私の裁量(特に override)は DCA に勝てているか」を、サンプル不足なら正直にそう言って。
```

## G. 集中度だけ見たい(mirror)
```
mirror を走らせて、今の look-through 集中度(セクター/通貨/地域/銘柄)と上限超過を教えて。
```

---

## 使い方の型(1回の検討の流れ)
```
市況(A) → 候補を分析(B) / 保有を点検(C) → 売買案を規律に通す(D)
   → 自分で決める → 記録(E) → 期日に採点・較正(F)
```
迷ったら最初に **G(mirror)** で「自分が今どこに偏っているか」を見てから。
