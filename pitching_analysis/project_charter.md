- 復帰過程: 1月末から復帰練習開始、約4ヶ月経過。Week 6 で紅白戦8イニング完投。直近予選で5回1安打3四死球無失点。次の予選まで約6週間。

## 2. これまでの対話で構築された認識（前提）

### 球速向上の戦略
- 球速向上には「新しい力を足す」と「漏れを塞ぐ」の二種類。本人は**後者のフェーズ**。
- スクワット200kg/デッド175kgの基礎出力は過去139km/h時点と変わらない（要実測確認）。不足は出力ではなく**出力の伝達効率**。
- よって新規筋力獲得より、**既存の力を指先まで届ける伝達効率の改善**が優先。

### フォームの現状と課題（優先順）
1. **胸の早い開き**: フットプラント時点で胸がキャッチャー方向へ。うで体特性も相まって捻転差が生まれる前に上半身が回る。
2. **アーム投げの軌道**: 肘が伸びた状態で腕が水平に広がる。慣性モーメントが大きいまま回旋→肩負担とエネルギーロス。
3. **捻転差の体感不足**: ゆっくりなら腹斜筋の引っ張りを感じるが、投球速度では意識的短縮が抜けず、受動的解放（伸張反射・SSC）が起きていない。
4. **ツッコミ気味**（上半身が前に出る）。
- これらはすべて「**アーム投げ→連鎖投げ**への切り替え」の不完全さから生じる。

### 確立済みの原則
- 腕の動きを意識で制御しない。腕の位置・角度・軌道は下半身始動と腕の脱力の結果。
- 意識すべきは**左腕の壁ただ一つ**（胸の開き・捻転差・前傾・加速距離すべての入口）。
- 捻転差は「作る」ものではなく「邪魔しない」もの。
- 痛みのある範囲で投げると脳の脅威予測が強化される。痛みの出ない範囲で正しいパターンを反復し可動域を広げる。
- 37歳の戦略は**質と回復**（投げ込みより一球の質、短時間集中、疲労を貯めない）。

### 肩の状態とローテーターカフ
- 5回投球翌日にローテーターカフが強く疲労、メディシン投げでも筋肉痛レベル。一方で肩甲骨周りの疲労は少ない。→ 典型的な「腕投げ」の疲労パターン（本来肩甲骨周りの大筋群が担う仕事をカフが代償）。
- 予選後7日で疲労が取れ始め、14日で完全回復。「疲労感・硬さが取れないと痛みは引かなかった」→ 痛みは炎症/損傷ではなく機能的問題（疲労と硬さ）の結果と判断。

## 3. 目標

- **短期（6週間後の予選）**: 9回投げ切る連動を達成。球速目標ではなく**質と持続性**の目標。
- **長期**: 145km/h 達成、全国大会優勝。
- 意向配分: フォーム再構築 70% / 筋力向上 30%。プッシュ系・プル系のボリュームを肩の調子に合わせて調整。

## 4. 最重要テーマ — 骨盤と上半身の分離（セパレーション）

捻転差の核心。9回投げ切る連動とも、うで体の構造的課題とも直結。

**NEOLAB AI 提案の4週間計画**
1. 週: 可動域・柔軟性引き上げ（骨盤回旋・胸郭回旋）
2. 週: 軽負荷ドリルで分離体感（壁叩き・線描き・ジャンプ）
3. 週: 重負荷・スピードアップ（メディシン・サイドジャンプ）
4. 週: 実投型応用、動画・感覚で実戦への転用確認

**チャット型 Claude からの補強提案**
- 胸椎の回旋・伸展可動域改善を骨盤左右差対策と同等以上に重視（猫背型は胸椎回旋を制限）。
- 鴻江理論を絶対視せず、動画・可動域チェックの実測で制限を確認。
- 左右非対称トレーニングは専門家評価かツール（リアラインコア）導入後に判断。
- プッシュ/プルのボリューム増は分離を妨げない範囲に抑える。

## 5. 未解決の論点・検証すべき仮説（初期セット）

- **仮説1**: ローテーターカフの疲労はフォーム非効率（アーム投げ、肩甲骨機能不全）の結果。フォーム改善で同球数でもカフ疲労は減る。
- **仮説2**: 胸椎可動性改善が骨盤と上半身の分離を最も大きく促進する。
- **仮説3**: プッシュ系のボリューム増は肩前面のタイトネスを生み分離を阻害。プル系（特に懸垂系）の方が投手に安全。
- **仮説4**: 軽い痛みが残る状態での投球は脳の脅威予測を強化し、無意識のブレーキを持続させる。完全無痛が出力解放の前提。
- **仮説5**: 「9回投げ切る連動」には 1イニング平均10〜12球以下の制球精度が必要。フォーム改善は球数削減を通じて完投を可能にする。
- **仮説6**: リアラインコア導入がうで体の左右差を改善し、開きとツッコミを軽減する。
- **仮説7**: 複数AI（Claude、NEOLAB）の見解は概ね科学的根拠と整合するが各々に強みと盲点。統合が個別最適に繋がる。
- **仮説8**: 37歳の身体は中3日では完全回復しない。回復期間設計が球速とフォーム維持に決定的。

## 6. 未議論・見落とし候補の領域（Claude Code が盲点として探索する）

## 8. Claude Code への依頼（3フェーズ）

各フェーズの成果物は、出力前に簡潔なサマリーを提示し、本人の確認を得てから本格出力する。

- **フェーズ1**: 批判的分析と盲点の発見 → `analysis_phase1.md`
  - 観点: 論理的整合性／科学的根拠の妥当性／個別性への対応／盲点／リスク評価／複数AI見解の質／時間配分。
  - 率直・批判的に。可能な限り具体的な研究・理論を参照。エビデンスが弱い部分は明示。
- **フェーズ2**: 仮説の整理と優先順位付け → `hypotheses_priority.md`
  - 形式: 仮説名／内容（命題）／背景・根拠／検証方法／期待成果／優先順位（理由つき）。
  - 優先基準: 短期目標への影響度／実現可能性／インパクト／リスク／長期目標への寄与度。最低5・最大15程度。
- **フェーズ3**: データ記録システムの設計 → `data_system_design.md` ＋ `templates/` ＋ `examples/` ＋ `scripts/` ＋ `README.md`
  - 記録項目（必須/任意）、形式（md/CSV/JSON）、Obsidian管理（ファイル構成・テンプレ・リンク・タグ）、頻度、分析方法、可視化。
  - **1日5〜10分以内で完了**する継続可能な設計を最優先。
